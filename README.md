# SkyVortex Portfolio (React + Vite)

## Menjalankan di Termux

**Prasyarat:** Termux terbaru dan koneksi internet. Jalankan:

```bash
pkg update && pkg upgrade
pkg install nodejs-lts git unzip
cd ~/Portofolio_V5-main
npm install --legacy-peer-deps
cp .env.example .env
nano .env
npm run dev -- --host 0.0.0.0
```

Buka alamat lokal yang ditampilkan Vite (biasanya `http://localhost:5173`). Isi `.env` dengan URL Supabase dan publishable/anon key milik project Anda. Tanpa dua nilai itu, aplikasi memang tidak bisa memulai karena beberapa halaman memakai Supabase.

Jika project ZIP diekstrak ke folder lain, masuk ke folder yang berisi `package.json` sebelum menjalankan perintah npm.

## Build produksi dan pemeriksaan

```bash
npm run build
npm run lint
npm run preview -- --host 0.0.0.0
```

Build dan lint adalah pemeriksaan terpisah; perbaiki error yang dilaporkan sebelum deploy.

## GitHub dan Vercel

1. Buat repository baru di GitHub, lalu dari folder project jalankan:

   ```bash
   git init
   git add .
   git status
   git commit -m "Fix and prepare SkyVortex portfolio"
   git branch -M main
   git remote add origin https://github.com/USERNAME/NAMA-REPO.git
   git push -u origin main
   ```

   Ganti URL remote dengan repository Anda. Periksa `git status` dan pastikan `.env` **tidak** ikut ter-commit.

2. Di Vercel, pilih **Add New → Project**, import repository GitHub tersebut. Framework akan terdeteksi sebagai **Vite**. Build command: `npm run build`; output directory: `dist`.

3. Di **Vercel → Project → Settings → Environment Variables**, tambahkan:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

   Pilih environment yang dibutuhkan (Production, Preview, Development), simpan, lalu redeploy.

4. Pastikan tabel dan Row Level Security (RLS) Supabase sudah disiapkan sesuai kebutuhan aplikasi. Jangan pernah memasukkan `service_role` key ke variabel `VITE_*`; variabel tersebut terekspos ke browser. Gunakan publishable/anon key dengan kebijakan RLS yang benar.

`vercel.json` mengarahkan route aplikasi kembali ke `index.html`, sehingga route React seperti `/project/...` dapat dimuat langsung.

## Getting Started

### Prerequisites

- Node.js `>= 14.x`
- npm or yarn

### 1. Clone & Install

```bash
git clone https://github.com/SkyVortex/consolelogskyvortex-portfolio.git
cd Portofolio_V5
npm install
```

> If you encounter peer dependency issues: `npm install --legacy-peer-deps`

### 2. Environment Variables

Create a `.env` file in the root directory:

```env
VITE_SUPABASE_URL=your-supabase-project-url
VITE_SUPABASE_ANON_KEY=your-supabase-anon-key
```

> Find these in your Supabase project under **Settings → API**.  
> ⚠️ Never commit `.env` to version control — make sure it's in `.gitignore`.

### 3. Supabase Client (`src/supabase.js`)

```javascript
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY

if (!supabaseUrl || !supabaseKey) {
  throw new Error('Supabase credentials missing. Check your .env file.')
}

export const supabase = createClient(supabaseUrl, supabaseKey)
```

### 4. Database Setup

Go to your Supabase project → **SQL Editor** → run the script below (run once):

```sql
-- ============================
-- TABLES
-- ============================
CREATE TABLE public.projects (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Title" text,
  "Description" text,
  "Img" text,
  "Link" text,
  "Github" text,
  "Features" jsonb,
  "TechStack" jsonb,
  is_published boolean DEFAULT true,
  order_index int DEFAULT 0,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.certificates (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "Img" text,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.portfolio_comments (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  content text NOT NULL,
  user_name text NOT NULL,
  profile_image text,
  is_pinned boolean DEFAULT false,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE public.profiles (
  id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  username text UNIQUE NOT NULL,
  role text NOT NULL CHECK (role IN ('admin', 'user')),
  created_at timestamptz DEFAULT now()
);

-- ============================
-- RLS
-- ============================
ALTER TABLE public.projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.certificates ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.portfolio_comments ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

-- Authenticated users may only read their own profile.
-- This is required by the login flow to check the user's role.
CREATE POLICY "User can read own profile"
ON public.profiles
FOR SELECT
TO authenticated
USING ((SELECT auth.uid()) = id);

CREATE POLICY "public read projects"
ON public.projects FOR SELECT USING (true);

CREATE POLICY "public read certificates"
ON public.certificates FOR SELECT USING (true);

CREATE POLICY "public read comments"
ON public.portfolio_comments FOR SELECT USING (true);

CREATE POLICY "public insert comment"
ON public.portfolio_comments FOR INSERT
WITH CHECK (is_pinned = false);

CREATE POLICY "admin manage projects"
ON public.projects FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage certificates"
ON public.certificates FOR ALL
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "admin manage comments"
ON public.portfolio_comments FOR ALL
TO authenticated
USING (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
)
WITH CHECK (
  EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

-- ============================
-- STORAGE
-- ============================
INSERT INTO storage.buckets (id, name, public)
VALUES ('project-images', 'project-images', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "admin upload project images"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'project-images'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "public read project images"
ON storage.objects FOR SELECT
USING (bucket_id = 'project-images');

INSERT INTO storage.buckets (id, name, public)
VALUES ('certificate-images', 'certificate-images', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "admin upload certificate images"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'certificate-images'
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE id = auth.uid() AND role = 'admin'
  )
);

CREATE POLICY "public read certificate images"
ON storage.objects FOR SELECT
USING (bucket_id = 'certificate-images');

INSERT INTO storage.buckets (id, name, public)
VALUES ('profile-images', 'profile-images', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "public upload profile images"
ON storage.objects FOR INSERT
TO public
WITH CHECK (bucket_id = 'profile-images');

CREATE POLICY "public read profile images"
ON storage.objects FOR SELECT
TO public
USING (bucket_id = 'profile-images');

-- Optional: default pinned comment
INSERT INTO public.portfolio_comments (
  content,
  user_name,
  profile_image,
  is_pinned,
  created_at
)
SELECT
  'developed by Consolelogskyvortex. This project is open-source and free to use.',
  'Consolelogskyvortex',
  'https://egwzigagwyrmwjsrebzx.supabase.co/storage/v1/object/public/profile-images/profile-images/1771939421615_xx2q8hgya6e.jpeg',
  true,
  now()
WHERE NOT EXISTS (
  SELECT 1
  FROM public.portfolio_comments
  WHERE is_pinned = true
);
```

**Step 2** — Run this in the SQL Editor (replace `USER_UUID` with the copied ID):


## Audit keamanan dan deployment (penting)

- Jangan pernah memasukkan Supabase `service_role` key atau secret key ke variabel `VITE_*`; variabel Vite dikirim ke browser. Gunakan hanya URL project dan publishable/anon key.
- Pemeriksaan role pada React hanya mengatur tampilan/rute, bukan batas keamanan database. Wajib aktifkan Row Level Security (RLS) untuk tabel `profiles`, `projects`, `certificates`, dan `portfolio_comments`, serta buat policy yang membatasi INSERT/UPDATE/DELETE administratif pada user yang role-nya admin. Jangan mengandalkan `ProtectedRoute` saja.
- Batasi kebijakan Storage bucket `project-images`, `certificate-images`, dan `profile-images`: hanya admin boleh mengunggah/menghapus file administratif. Untuk komentar publik, tetapkan batasan dan validasi ukuran/tipe file serta kebijakan insert yang sesuai agar tidak menjadi jalur spam/penyalahgunaan.
- Isi `VITE_SUPABASE_URL` dan `VITE_SUPABASE_ANON_KEY` di `.env` lokal dan Environment Variables Vercel. Jika belum diisi, halaman publik tidak lagi gagal saat mengimpor modul Supabase, tetapi fitur yang membutuhkan backend tentu tidak akan berfungsi.
- Setelah mengunduh project, jalankan `npm ci` (atau `npm install --legacy-peer-deps` bila npm menemukan konflik peer dependency), lalu `npm run build` dan `npm run lint`.

## Catatan hasil audit

Audit ini memperbaiki penanganan konfigurasi Supabase yang sebelumnya menghentikan aplikasi saat environment variables kosong, alur error/loading pada login dan route admin, penanganan upload project/sertifikat, path upload foto komentar, serta cache `localStorage` yang rusak. Build produksi belum dapat diverifikasi di lingkungan audit ini karena paket npm tidak dapat diunduh dari registry (DNS `EAI_AGAIN`); jalankan pemeriksaan di atas pada Termux atau CI dengan akses internet sebelum deploy.
